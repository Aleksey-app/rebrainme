# Weather Proxy
### Сравнительная таблица инструментов

| критерий | OpenCode | Aider | Cline |
| :--- | :--- | :--- | :--- |
| **Setup friction (шагов до первого результата)** | **Средний.** Требует установки, настройки конфигурационного файла и ключей API. Запуск в терминале, удобно и понятно. | **Низкий/Средний.** Установка через `pip/uv`. Быстрый запуск (`aider`), но требует настройки `.env` (ключи), понимания команд `/add`, `/clear`. Упёрся в лимиты токенов. Ушло пару дней с непривычки | **Низкий.** Установка расширения в VS Code в 1 клик. Настройка через GUI (выбор провайдера, вставка ключа). Сразу виден контекст и файлы. |
| **Как подтверждаются edits / shell и виден ли план** | **Явно виден план.** Агент предлагает пошаговый план, просит подтверждения на запуск команд и правки. Высокая степень контроля. | **Скрытый план.** Aider сам решает, что менять, и применяет правки автоматически (или спрашивает `y/n` для новых файлов). Shell-команды выполняет сам. План виден только в логах «Thinking» после факта. | **Явный план и подтверждения.** Cline показывает пошаговый план в чате, спрашивает `Approve` на каждую команду терминала и каждое изменение файла (diff). Полный контроль. |
| **Audit trail и rollback (как понять и откатить)** | **Встроенный git.** Агент сам коммитит изменения с понятными сообщениями. Легко откатить через `git log` / `git reset`. История диалога хранится локально. | **Автокоммиты.** Aider делает коммит после каждого изменения (по умолчанию). Легко откатить через `/undo` или `git reset`. Проблема: может «намусорить» лишними коммитами. | **История чата + git.** Cline не коммитит сам, оставляя контроль. Есть история изменений в UI (checkpoints), можно откатить файл кнопкой. Плюс стандартный `git diff`. |

**Инструмент Cline для сценария контролируемой разработки в IDE**
*   **Почему:** Он обеспечивает максимальный контроль (human-in-the-loop) через подтверждение каждого действия (edits/shell), наглядно показывает планы имеет в наборе бесплатные модели, не пытаясь самовольно их что-то «улучшить». 
*   **Trade-offs:** Медленнее из-за постоянных подтверждений. Требует открытого редактора VS Code. При лимитах Groq (8000 TPM) Cline спас, может быстрее съедать токены в сложных задачах.

**Инструмент Aider для рутинного рефакторинга в терминале**
*   **Почему:** Идеально подходит для тех, кто умеет пользоваться. Автоматически делает коммиты (удобный audit trail), позволяя быстро накидать базовый код.
*   **Trade-offs:** Склонен к «самодеятельности» (самовольно правил `settings.py` и ломал markdown, пытаясь «улучшить» README). Терминальный интерфейс (TUI) и необходимость ручного управления контекстом (`/clear`, `/drop`) требуеться очистить контекст '/сlear'. Автоматические коммиты могут засорить историю git, если не настроить.

**Инструмент OpenCode для терминальной разработки с акцентом на прозрачность (через TUI)**
*   **Почему:** Это современный агент, который делает упор на наглядный пошаговый план и запрос подтверждений, сочетая скорость терминала с безопасностью IDE-плагинов. Имеет хорошую поддержку провайдеров (включая локальные модели).
*   **Trade-offs:** Не интегрирован в редактор (нет подсветки diff прямо в коде).
